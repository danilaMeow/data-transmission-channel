
# Канал передачи данных с временными ограничениями

Практическая работа № 4 по системам реального времени.

Программа рассчитывает временные характеристики передачи сообщений в канале реального времени: время передачи, задержку доставки, время доставки при приоритетном арбитраже, джиттер и соблюдение дедлайнов.

## Модель

Каждое сообщение описывается четырьмя параметрами:

| Параметр | Описание |
|---|---|
| `name` | Имя сообщения |
| `priority` | Приоритет (1 - высший) |
| `size_bits` | Размер сообщения в битах |
| `period_ms` | Период сообщения в миллисекундах |

Канал передачи данных описывается следующими параметрами:

| Параметр | Описание |
|---|---|
| `speed_bps` | Скорость передачи в бит/с |
| `propagation_delay_ms` | Задержка распространения в мс |
| `processing_delay_ms` | Задержка обработки в мс |

Сообщения и параметры канала представлены классами `Message` и `Channel` с использованием `@dataclass`.

## Расчётные формулы

### Время передачи

Время передачи сообщения определяется по формуле:

`t = L / R * 1000`

где L - размер сообщения в битах, R - скорость канала в бит/с. Результат выражается в миллисекундах.

### Задержка доставки

`D = t + D_prop + D_proc`

Задержка доставки складывается из времени передачи, задержки распространения и задержки обработки.

### Приоритетный арбитраж

Время доставки рассчитывается итерационным методом:

`W(k+1) = C_i + Σ ceil(W(k) / T_j) * C_j`

где:

- `C_i` - время передачи рассматриваемого сообщения;
- `C_j` - время передачи более приоритетного сообщения;
- `T_j` - период более приоритетного сообщения.

Итерации начинаются с `W(0) = C_i` и продолжаются до стабилизации результата.

Полученное время дополняется задержками распространения и обработки.

Модель учитывает повторное поступление более приоритетных сообщений, но не учитывает блокировку уже начавшейся передачей низкоприоритетного сообщения.

### Джиттер

`J = D_max - D_min`

В программе оценивается разброс между задержкой доставки без конкуренции и расчётным временем доставки с арбитражем.

### Проверка дедлайна

`D_arbitration ≤ deadline`

В демонстрационном наборе дедлайн сообщения принимается равным его периоду.

## Запуск

Требуется Python 3.10 или новее.

Сторонние библиотеки не используются.

Запуск из корневого каталога репозитория:

```powershell
python src/main.py
```

Для отдельной проверки чтения данных:

```powershell
python src/loader.py
```

## Формат входных данных

Программа загружает сообщения и параметры канала из файла:

`data/messages.csv`

Заголовок CSV:

```csv
name,priority,size_bits,period_ms,speed_bps,propagation_delay_ms,processing_delay_ms
```

Пример:

```csv
name,priority,size_bits,period_ms,speed_bps,propagation_delay_ms,processing_delay_ms
M1,1,1000,10,500000,0.1,0.2
M2,2,2000,20,500000,0.1,0.2
M3,3,4000,50,500000,0.1,0.2
```

Параметры канала повторяются для каждого сообщения.

При загрузке выполняются проверки:

- наличия необходимых столбцов;
- корректности числовых значений;
- уникальности имён и приоритетов;
- положительности размеров, периодов и скорости;
- неотрицательности задержек;
- одинаковых характеристик канала для всех сообщений.

## Исходные данные

Скорость канала - 500 000 бит/с.

Задержка распространения - 0,1 мс.

Задержка обработки - 0,2 мс.

| Сообщение | Приоритет | Размер, бит | Период, мс |
|---|---:|---:|---:|
| M1 | 1 | 1000 | 10 |
| M2 | 2 | 2000 | 20 |
| M3 | 3 | 4000 | 50 |

## Результаты

| Сообщение | Передача, мс | Доставка, мс | Арбитраж, мс | Джиттер, мс | Дедлайн, мс | Уложилось |
|---|---:|---:|---:|---:|---:|---|
| M1 | 2.000 | 2.300 | 2.300 | 0.000 | 10 | Да |
| M2 | 4.000 | 4.300 | 6.300 | 2.000 | 20 | Да |
| M3 | 8.000 | 8.300 | 16.300 | 8.000 | 50 | Да |

Итого по набору:

- сообщение M1 не испытывает задержек из-за более приоритетных сообщений;
- для M2 дополнительная задержка составляет 2 мс;
- для M3 дополнительная задержка составляет 8 мс;
- наибольшее расчётное время доставки составляет 16,3 мс;
- наибольшая оценка джиттера составляет 8 мс;
- все три сообщения укладываются в установленные дедлайны.

## Функции

- `Message` (`model.py`) хранит имя, приоритет, размер и период сообщения.
- `Channel` (`model.py`) хранит скорость передачи и задержки канала.
- `load_tasks` (`loader.py`) загружает CSV и проверяет корректность входных данных.
- `transmission_time` рассчитывает время передачи сообщения.
- `delivery_delay` рассчитывает задержку доставки без конкуренции.
- `arbitration_time` определяет время доставки с учётом более приоритетных сообщений.
- `jitter` рассчитывает разброс переданных значений времени доставки.
- `meets_deadline` проверяет соблюдение дедлайна.
- `main` выводит характеристики канала, таблицу результатов и заключение.
